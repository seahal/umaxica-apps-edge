# キーボード操作の準拠方針

**位置づけ：規範。**
UMAXICA Edge の UI は、[Apple Human Interface Guidelines の Keyboards](https://developer.apple.com/design/human-interface-guidelines/keyboards) に準拠して設計、実装、レビューする。
対象は、このリポジトリが HTML を生成するすべての deployment unit とする。
本書は今後の変更に適用する方針であり、既存 UI の準拠確認が完了したことを示すものではない。

## Apple の指針の適用

Apple の指針では、標準ショートカットの尊重、頻繁に使う機能に絞った独自ショートカット、Full Keyboard Access への対応が示されている。
原文の確認日は 2026-10-19 とする。
指針を更新するときや新しいキー割り当てを決めるときは、上記の一次資料を再確認する。

本リポジトリでは、これらをブラウザー上の UI に適用する。
Apple のネイティブ API や iPadOS のフォーカス制御に固有の説明は、そのまま Web の実装要件にはしない。
特に iPadOS のネイティブコントロールに関する注意書きを理由に、HTML のボタンをキーボードで操作できなくしてはならない。
既存の [UI shell contract](ui-shell-contract.md) と併せて適用する。

## 標準操作と独自ショートカット

OS、ブラウザー、入力方式が提供する標準操作を維持する。
コピー、貼り付け、検索、タブ移動、入力ソースの切り替えなどを、別の機能に割り当てない。
Web UI ではブラウザーの操作も利用者の期待に含まれるため、アプリ内の都合でキーイベントを一律に抑止しない。

独自ショートカットは、頻繁に使う固有の機能に必要な場合だけ追加する。
Apple 環境では Command を主な修飾キーとする指針を踏まえ、対象 OS、ブラウザー、キーボード配列との競合を確認して決定する。
他の環境への割り当ても個別に確認し、Command を機械的に Control に置き換えない。
複数の修飾キーを表記する場合は Control、Option、Shift、Command の順とする。

次の項目は、このリポジトリでの実装ルールとする。

- ショートカットには通常のボタンやメニューからも実行できる経路を設ける。
- 操作名とキーの組み合わせを UI で確認できるようにする。
- 入力欄や編集可能領域での文字入力と IME の変換確定を妨げない。
- `preventDefault()` は、そのイベントを UI が処理する必要がある場合に限定する。
- キー割り当てを追加するときは、目的、対象環境、競合確認の結果を変更説明に記載する。

## Web UI のフォーカス管理

キーボードだけで主要な操作を完了できるようにする。
この要件を Web で確認できる形にするため、次をリポジトリのルールとする。

- リンクやボタンには意味に合った HTML 要素を使い、標準のキー操作を維持する。
- Tab と Shift+Tab で論理的な順序に移動でき、現在のフォーカス位置が視覚的に分かるようにする。
- スキップリンクから本文へ移動できるようにする。
- メニューやダイアログでは、開いた後のフォーカス、閉じる操作、閉じた後の戻り先を定義する。
- モーダル以外でフォーカスを閉じ込めず、モーダルにはキーボードで閉じる経路を設ける。

既存の semantic HTML と、UI shell contract が定めるコンポーネントの振る舞いを優先する。
キー処理の共通ライブラリーを、この方針の追加だけを理由に導入しない。

## 変更時の確認

キーボード操作に関係する UI を変更した場合は、対象画面を実際のブラウザーで操作して確認する。

- マウスなしで移動、実行、終了でき、フォーカスを見失わないこと。
- 標準ショートカット、文字入力、IME の変換操作を妨げないこと。
- 独自ショートカットがある場合は、対象の OS とキーボード配列で意図どおり動くこと。
- Apple 環境での Full Keyboard Access の確認結果を記録し、実機で確認できなかった場合は未確認と明記すること。

ブラウザーのフォーカスやキー操作の回帰テストは、各 unit の Playwright テストに置く。
文書の追加や静的なコード確認だけで、実機での準拠確認を済ませたとは扱わない。
保持する価値のある確認結果は、実行した環境、対象画面、結果、未確認事項を `evidence/` に記録する。
